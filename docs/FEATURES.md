# 現在の機能と仕様（実装済みの範囲）

「いま本番で何ができるか」の一覧。要件の原文・確定事項は [REQUIREMENTS](REQUIREMENTS.md)・[DECISIONS](DECISIONS.md)、API契約は [API](API.md)、権限は [AUTHZ](AUTHZ.md)。スコープ外・未実装は末尾。

## ロール

Owner / Admin / Editor / Member。Ownerだけが、Adminの追加・剥奪とOwner継承を操作できる。管理者権限を持つユーザーに対する停止・招待・再設定はOwnerだけ。認可はすべて**Go APIで強制**し、認可表（`services/api/internal/authz`）がAPIの全エンドポイントと1対1で対応することをテストで検査している。

## 内部ポータル（`app.nu-digital.jp`）

| 領域 | できること |
|---|---|
| **ログイン・アカウント** | Adminが発行した`nu_digital ID`＋本人が設定するパスワード。期限付き・使い捨ての招待URL／パスワード再設定URL（Adminが本人確認のうえ個別に送る。メール自動配信なし）。セッション・CSRF・レート制限。公開の自己登録は無い。初期OwnerはCLI（`nuctl bootstrap-owner`）でだけ作れる。Owner継承は二段階（申請→24時間以内に相手が承諾）。緊急復旧CLI（`nuctl recover-owner`） |
| **メンバー・プロフィール** | 表示名・アバター・学部・学科・学年・機材・自己紹介・外部リンクなど。**項目ごとの公開範囲**（本人／メンバー／インターネット）。学生証番号・大学メール・最寄り駅は一般メンバーに出ない。卒業・退会はAdminが停止（セッション失効・履歴は維持）。個人情報の手動削除（監査証跡は残し、値は残さない） |
| **アカウント設定（UI/UX改善）** | 「項目名・現在の内容・公開範囲・変更」の行形式（プロフィール／公開設定／個人情報／アカウントの4画面）。変更はダイアログ（保存・キャンセル・入力エラー）。アイコンはトリミングつき。公開設定は、どこに何が表示されるかの一覧つき。パスワード・ぬでじIDの変更は管理者に依頼（APIなし） |
| **物品の貸出** | 写真中心・スマホ優先のカード一覧（複数画像・メイン写真）、検索・カテゴリ・「借りられる物だけ」・「自分が借りている物」・並び替え、状態の明示（貸出可能／一部貸出中／すべて貸出中／自分が借りている）、詳細（画像ギャラリー・数のステッパー）。カテゴリは管理者が追加・名称変更・並び替え・削除（既定: 機材・書籍・その他）。数量管理と個体管理の切り替え。**承認なしで貸出・返却を登録**（他人の借用品の返却登録も可）。経過日数の表示（期限・延長・QRなし）。訂正イベントと履歴。Adminは物品の追加・編集・廃止・数量調整・訂正 |
| **記事・作品のCMS** | Markdown本文・画像・URLスラッグ・カテゴリ。下書きと公開の分離（公開中の版を編集しても再公開まで従来の版が表示される）。共同編集者・保存競合の検知・編集履歴と公開履歴。作品の制作メンバーと役割（本人の公開クレジット同意は別）。YouTube埋め込みのみ（他は通常リンク）。公開済み記事の本人情報の確認 |
| **記事・作品の一覧・編集（UI/UX改善）** | 一覧はカード（カバー画像・タイトル・状態・日付・関わるメンバーのアバター重ね表示）。タイトル検索・区分・公開中/下書き・自分が関わる物で絞り込み。**日付はユーザーには1つ**（内部の表示ラベル・種類は自動。既存記事は触らなければそのまま）。**共同編集者と制作メンバーを「メンバー」に統合**（追加=編集できる、作品では役割を入れるとクレジット。公開サイトに名前が出るのは本人の同意があるときだけ）。プレビューは下書き画像・既存記事の画像（`/images/…`）も表示、PC/スマホ幅の切り替え |
| **記事・作品の一覧・編集（第2フェーズ）** | 一覧は**記事と作品が混在して、利用者に見せる日付の新しい順**。上部で「すべて／記事／作品」「公開中／下書き」に絞り込み、カードに種類の札。三点メニューから**削除**（論理削除。公開中は公式サイトからも消える旨を確認。下書きは作者・Editor以上、公開中はEditor以上）。編集画面は**上にメタ情報（タイトル・カバー・日付・メンバー・要約。たためる）、下に本文（左）とプレビュー（右）**で、スクロールを連動。スマホは編集/プレビューのタブ。**画像は本文へドラッグ＆ドロップ・貼り付け・ファイル選択（複数可）**で、カーソル位置にMarkdown記法が自動で入り、進捗・失敗時の再試行・最適化後のサイズを表示。カバーもドロップで設定。ボタンは「下書き保存」と「公開する／公開内容を更新」だけ（内部の版番号は表示しない）。未保存の変更は、離れるときの警告とブラウザーへの控え（復元）で守る |
| **画像（メディア）** | JPEG・PNG・WebPのアップロード（アバター5MiB・物品/CMS画像10MiB・2,000万画素まで）→ 再エンコードしてWebPで保存。非公開と公開の分離・参照整合性の確認CLI（`nuctl media-verify`・`media-gc`） |
| **Discord通知** | 貸出・返却などのイベントを、設定したチャンネルへ。種別ごとにON/OFF・送信先を設定。**outbox経由**で、通知が失敗しても業務操作は成功する。送信状況・再送 |
| **管理** | ユーザー管理、物品の管理、通知の設定、既存記事の投稿者の管理（公開許可の記録）、公開済みコンテンツの検索 |
| **ダッシュボード** | ログイン後のトップ（団体の写真・アプリランチャー）。記事・作品の自動表示（`dashboard feed`）は**未実装** |

## 公式サイト（`nu-digital.jp`）

既存サイトのデザイン・ページ構成・主要URL（記事67件・画像・ギャラリー）を維持したまま、**公開版のAPIから描画**する。下書きは返さない。投稿者名は、本人の公開許可が記録されるまで「nu_digital」と表示。既存サイトとの一致は、移設前の基準（74ルート・67記事・532画像）と常時比較している（`compose / smoke`）。

## 運用・基盤の機能

- **デプロイ**: mainへのマージ → CI → 承認 → 自動デプロイ・失敗時は前の版へ自動復帰・手動の切り戻し。
- **バックアップ**: 毎日03:00(JST)・7世代・DBと画像を一組・隔離環境での復元検証（ぬるのデータも含む）。
- **監視・通知**: バックアップの失敗・デプロイの成否・TLS証明書の期限（14日前から）をDiscordの運用チャンネルへ。
- **セキュリティ**: Nginxで公開ホストはGET/HEADのみ・公開APIは画像配信だけ・レート制限・HSTS。Dockerのポートは127.0.0.1のみ。コンテナは`cap_drop: ALL`・`read_only`。

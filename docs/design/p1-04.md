## 対象操作と利用場面

1. 部室や自宅のPC・スマホで、配られた招待URLを開いてパスワードを設定する（初回）
2. ログインして、団体の写真が大きく出るランチャーから使いたいアプリを選ぶ
3. パスワードを忘れたとき、管理者から受け取った再設定URLで新しいパスワードを設定する
4. ログアウトする

## 設計判断（暫定）

- **ログイン**: ID・パスワードの2項目。ラベルは入力の上に常に表示（プレースホルダーに頼らない）。パスワードは「表示する」切替を用意（貼り付けは禁止しない）。送信中はボタンを無効化し二重送信を防ぐ。失敗は「ログインIDまたはパスワードが違います」と1つの文言（理由を区別しない＝サーバー仕様）。429は「試行が多すぎます。しばらくしてからお試しください」。失敗時は入力を保持し、エラー領域へフォーカス移動（`role="alert"`）。
- **ランチャー**: 上部に団体写真を大きく（全幅、スマホでも画面の約40%）、その下に全員共通のアプリカード（物品・記事と作品・メンバー・プロフィール）。実装前のものは「準備中」と明示し押せない（権限・可否はAPIで強制し、画面の非表示で代替しない）。カードは最低44px以上のタップ領域、PCは3〜4列・スマホは1列。ヘッダーに表示名とログアウト。
- **招待/再設定**: トークンはURLのフラグメントから読み、画面に表示しない。パスワードは2回入力（確認）。方針違反はサーバーの文言をそのまま表示。完了後はログインへのリンクを表示（自動ログインしない＝P1-02の暫定仕様）。`Referrer-Policy: no-referrer`と`Cache-Control: no-store`。
- **見た目**: 団体カラー`#004aad`を主色。背景は白、本文は#1a1a1a。フォーカスは常に見える2pxの輪郭。`prefers-reduced-motion`で動きを止める。余白・角丸・文字サイズはCSS変数。画像は代替テキスト付き。
- **採用しないこと**: 既存の公式サイトの画像・画面そのものの転載は、ヒーロー写真1枚とロゴのみ（D13で継続公開が許可された団体素材）。他のサービスの画面・ロゴは使わない。

## 実装メモ

- apps/adminのNextが`/api/v1/*`をAPIへ中継（ブラウザーから同一オリジン。本番のNginx構成と同じ。`API_INTERNAL_URL`で指定）
- 認証状態はAPIの`GET /auth/me`で判断する（Cookieは`HttpOnly`でJSから読めない）。CSRFトークンは`/auth/me`・ログイン応答の`csrfToken`をメモリに保持して`X-CSRF-Token`に付ける
- 画面確認: PC1440×900・スマホ390×844・幅320px、キーボードのみ、200%拡大。**画面E2E（`npm run compose:smoke`に含まれる）が撮るスクリーンショットは`.local/ui-shots/`（Git管理外）に保存**し、目視で確認する（実施結果は`docs/handoffs/49-progress.md`）

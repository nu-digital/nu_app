# 第3フェーズ P0: ぬるの安全性・人格・記憶の設計

2026-11-29。対象: `services/agent`。現状は [NUL_OVERVIEW](../NUL_OVERVIEW.md)、判断は [DECISIONS NUL-15](../DECISIONS.md)。**この文書は、依頼（§2.1〜2.5）に対する現状調査・実装した変更・残る課題の記録**。

## 2. 実装した変更（P0）

1. **DM廃止（権限・イベント段階で3層）**: ①Gateway Intentsから`IntentsDirectMessages`を除去（DMイベントがそもそも届かない）。②`convert`が対象サーバー以外（DM含む）を破棄（記録・応答・記憶生成なし）。③`Responder.Decide`がDMを拒否。さらに`/nul`もサーバー外からは無視。テスト: `TestGatewayDropsDMAndForeignGuild`・`TestDecide`。
   - Discord Developer Portal側でBotの「DMを受けない」設定はできない（Intentsで届かなくなる）。ユーザーが先にDMを送ること自体はDiscordの仕様で防げないが、ぬるは何も処理しない。
2. **人格の改訂**: 冷めて自由・ノリがよい・雑談は短い・褒めない励まさない・ぬるぽ→ガッ。固定台詞にしない。会計・個人情報・セキュリティ・団体運営の話は正確に、が線。
3. **プロンプト簡略化**: 固定プロンプトを役割別（人格／線／入力とツール）に再構成して約半分に。ツールの使い方の細則は各ツールの`Description`へ。固定プロンプトに変わるもの（日時・気分・場所・人名）を入れない既存テストは維持。
4. **乱用上限**: リマインダー作成は1人1日10回（`daily_calls.kind='remind'`・migration 00023）。1回の返答のツール呼び出しは総数6回まで（ラウンド3回の上限と併用）。リマインダーに**繰り返し機能は無い**ので、頻度・間隔の乱用経路は無い（有効10件・最大1年先・最短1分後）。管理者も同じ上限。

## 3. プロンプトインジェクション対策の整理（既存＋追加）

層1: **ツールを最小に**（上記10個。会計・Drive・Sheets・デプロイ・SSHは与えない）。層2: **サーバー側の認可**（ユーザーIDは発言者から。LLM出力のIDは使わない）。層3: **量の上限**（予算・1人1日・ラウンド・ツール総数・リマインダー）。層4: **データの隔離**（`untrusted_message`）。層5: **停止**（`/nul stop`・フェイルセーフ）。層6: **自己改善は提案のみ**。

**会計機能とぬるの関係（重要な設計判断）**: 購入申請のAI補助（P2）は**ぬるのDiscord側と別の呼び出し**として実装し、使えるのは「申請の下書きを更新する限定ツール」だけ。**Discord上のぬるには会計ツールを与えない**（Discord投稿経由のインジェクションで申請・承認・Drive/Sheetsが動く経路を作らない）。承認・申請確定・領収書確認は人の操作だけ。

## 4. Botの最小権限（本番変更は運用責任者の承認が必要）

コードが使うREST操作から必要な権限を洗い出すと、**View Channels・Read Message History・Send Messages・Send Messages in Threads・Add Reactions**（＋スラッシュコマンドの登録はアプリ権限で足りる）。Embed Links・Attach Files・Manage系・Mention Everyone・Administratorは不要。Intentsは`Guilds`・`GuildMessages`・`GuildMessageReactions`・`GuildMembers`（新メンバーへの一言）・`MessageContent`（特権）。**提案: ロールからAdministratorを外し、上の権限だけを付与する**（実施は運用責任者。外した後の確認手順は RUNBOOK に追記予定）。非公開チャンネルをぬるが読めるかどうかは、ロールの権限設定に依存する（`is_public`判定は@everyoneの視点なので影響しない）。

## 5. 記憶・ログの方針（案。具体値は暫定）

| 種類 | 保存先 | 期間（案） | 備考 |
|---|---|---|---|
| 短期文脈 | `messages`（呼ばれたチャンネル/スレッドの直近） | 件数上限は既存実装（直近数十件）。トークン上限をプロンプト構築側で追加検討 | 他チャンネルの内容は混ぜない（既存） |
| 団体の長期知識 | 日次要約・週報月報 | 現状維持 | 公開チャンネルのみ |
| メンバーの記憶 | `notes`（本人についてのみ・個人情報の形は拒否・件数上限） | 本人が削除可（既存）。内容は常にデータ扱い | 不正な指示を保存する攻撃は、ノートを`untrusted`で渡す・ツール権限が最小であることで無害化 |
| 運用ログ | stdout（本文を出さない） | Docker既定 | 秘密を出さない（`redact`） |
| ツール実行の監査 | **未実装（課題）**: `agent.tool_audit`（ツール名・発言者ID・成否・時刻。引数の本文は保存しない）を追加予定 | 90日（案） | 管理者が監査できるように |
| 会計の正式記録 | **別系統**（nu_appの`audit`・会計テーブル。[phase3-accounting.md](phase3-accounting.md)） | 大学ルール確認まで削除しない | 雑談ログと保存方針を分ける |

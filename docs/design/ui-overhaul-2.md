# UI/UX改善 第2フェーズ（計画・設計・検証）

最終更新: 2026-11-28。前回: [ui-overhaul.md](ui-overhaul.md)。本番を実際に使った運用責任者の不満が出発点。進捗の記録は [194-progress](../handoffs/194-progress.md)。

## 0. デザイン原則（今後のnu_app全体）

> **ホーム画面は魅力的に、操作画面は直感的に、制作画面は集中しやすく。**

- nu_appは業務管理システム／SaaSの管理画面にしない。**Steamのようなゲームランチャーの世界観**と、**BOOTH・note・メルカリの分かりやすい操作性**を組み合わせる。nu_digitalはクリエイターの団体なので、情報を管理するだけでなく、活動やメンバーの作品に触れて制作意欲が湧くポータルにする。
- 画面の種類ごとに、設計の重みを変える。

| 画面の種類 | 例 | 優先すること | 作り方 |
|---|---|---|---|
| ホーム（見せる） | ランチャー | 魅力・世界観 | 大きな写真・作品画像、タイポグラフィ、アイコン、モーションを積極的に使う |
| 操作（使う） | 物品の貸出・返却、設定、メンバー | 分かりやすさ・操作の少なさ | 装飾より、状態の見やすさと「次にやること」のボタン。確認手順を減らす |
| 制作（作る） | 記事・作品の編集 | 集中 | メタ情報は上に畳み、本文とプレビューに広さを渡す。余計な表示を出さない |

- **すべての画面を同じカード／管理画面のテンプレートにしない。** 画面の目的に合うレイアウトを選ぶ。
- **開発者・DBの都合をUIに出さない。** 版番号、内部の状態、権限テーブルの構造、関連テーブルの都合は表示しない（必要な仕組みは内部に残す）。不要なページ・ボタン・設定・確認は消す。
- 見た目の部品は Charcoal（`components/ui`）を土台にする。色・余白・角丸は [DESIGN](../DESIGN.md) のトークンを使い、**状態は色だけで伝えない**。

## 2. 方針と設計

### 2.1 物品（PR-A）
- **migration 00022**: `inventory_categories.is_system`（「その他」だけtrue）、`inventory_returns.location`（text、既定''）。前進のみ。
- **カテゴリ削除**: 廃止済みの物品は数えない。使用中でも**自動で「その他」へ移す**（廃止済みの物品も移す＝外部キーとデータの整合を保つ。貸出履歴は物品IDで残るので壊れない）。「その他」はシステムカテゴリとして削除・名前変更不可。`moveTo` は後方互換のため任意で残す。UIは確認ダイアログのみ（件数と「その他に移す」を明記）。
- **状態の絞り込み**: 「貸出可能」「貸出中」「自分が借りている」の3つ（`status` = `available|loaned|mine`）。解除で全件。数量管理は「残り3/5」を一覧にも出す。
  - 貸出可能 = 借りられる数が1以上（一部貸出中を含む）／貸出中 = 貸出中の数が1以上（一部を含む）／自分 = 自分の未返却がある。
- **詳細からの貸出・返却**: 状態に応じた操作を1画面に出す（借りる／返す／追加で借りる・返す／貸出中の表示）。個体管理も詳細から返せる（`loanId` を返す）。返却は**場所つきのダイアログ**（初期値は現在の保管場所）。
- **返却場所**: `POST /inventory/loans/{id}/returns` に `location`（任意・50文字以内・改行不可）。記録は `inventory_returns.location`。**物品の現在の保管場所（`inventory_items.location`）を更新**する（空なら更新しない）。保管場所は物品単位（数量・個体とも）の既存仕様のまま。個体ごとの場所は持たない（暫定。DECISIONSに記録）。履歴・Discordの返却通知に場所を含める（変更があったときだけ）。
- **ナビ**: 一般メンバーのナビ・物品トップから「貸出中の一覧」を外す（URLと管理者の履歴・管理は維持）。

### 2.2 記事・作品（PR-B）
- **削除**: `DELETE /contents/{id}`（編集権限者。下書きだけの記事は作成者・共同編集者、**公開中の記事は公開権限（Editor以上）**）。内部は**論理削除**（`archived_at` と監査ログ）。公開側・一覧・メディアの公開判定・slug検索から除外。slugは予約されたまま（URLの再利用を防ぐ）。参照されている画像は残る（復旧のため）。復旧は運用者がDBで `archived_at` をNULLに戻す（RUNBOOKに手順）。UIは三点メニュー＋確認ダイアログ（公開中は「公式サイトからも見えなくなります」）。
- **版の非表示**: 画面から「版N」を消し、「公開中」「公開内容を更新できます」「未公開の変更あり」など状態で表す。履歴は日時・編集者で出す。衝突の説明も内部用語を使わない。
- **一覧の統合**: 混在・新しい順（日付）。上部のフィルター（すべて／記事／作品）と公開状態。カードに種別の札。
- **編集画面**: 上にメタ情報（タイトル・カバー・日付・メンバー・要約・公開URL）を畳める形で整理し、下に本文（左）とプレビュー（右）。広い画面では本文が主役。スマホは編集／プレビューのタブ。**スクロール同期**は本文の位置の割合でプレビューを追う簡易版。
- **画像**: 本文へのドラッグ＆ドロップ・貼り付け・ファイル選択（複数可）→ サーバーのアップロード（最適化済み）→ カーソル位置にMarkdown画像記法を挿入。進捗・失敗時の再試行。カバーもドラッグ＆ドロップ。プレビューへ即時反映。処理はサーバー側（セキュリティと一貫性のため。クライアントでは再エンコードしない）。
- **保存・公開**: ボタンは「下書き保存」と「公開する」（公開済みは「公開内容を更新」）の2つ。公開権限がなければ下書き保存のみ。下書き保存は公開ページに影響しない（既存の版の仕組み）。未保存の変更で離れるときの警告（`beforeunload`＋サイト内リンク）。

### 2.3 ホーム・モーション（PR-C）
- **メインビジュアル**: 全画面幅のヒーロー。公開中の作品・記事のカバー画像を最新順に最大6枚（API `GET /contents` の `coverUrl`。公開版のカバーだけを使い、公開範囲を守る）。クロスフェード（約0.8秒）、5.5秒ごとに自動、手動の前後・ドット、一時停止（ホバー・フォーカス・ボタン）。作品名・日付と、記事／作品へのリンク。管理者の手動設定は将来（BACKLOG）。画像が無ければ既存の団体写真。
- **アイコン**: 機能ごとに固定のアイコン（`lib/nav-icons`）。ホームのタイル・ヘッダー・サイドの案内で共通。
- **ホームの内容**: 重要度順に ①あなたの状況（借りている物・編集中の記事）②ヒーロー③ショートカット④最近公開された記事・作品。既存APIだけで作る。
- **モーション**: 方針は §3。

## 3. モーションデザイン

- **採用**: Motion（`motion`、React用の`motion/react`）。理由: Reactの状態に連動するクロスフェード・出入り（`AnimatePresence`）・並べ替え（`layout`）が必要で、CSSだけでは複雑になる。バンドルは `LazyMotion`＋`domAnimation`＋`m` で小さくする（約5KB台＋機能）。React 19・Next 16 に対応していることを導入時に確認する。
- **ページ遷移**: View Transition APIは、Next（App Router）での安定性とブラウザ差があり、遷移の中断・戻る操作で壊れやすいので**使わない**。**CSSの短いフェードイン**（`@keyframes`、140ms）を `main` の表示に付ける。ルーティング・状態に介入しない。
- **共通のトークン**: 時間 `fast=120ms / base=200ms / slow=360ms / hero=800ms`、イージング `out = cubic-bezier(.22,1,.36,1)`、`inOut = cubic-bezier(.65,0,.35,1)`。CSS変数（`--motion-*`）と `lib/motion.ts` の定数で共通化。
- **対象**: ダイアログ・メニューの開閉、トースト、カードのホバー（わずかな浮き）、ボタンの押下、フィルター時のカードの並び替え、ヒーローの切り替え、ナビの選択、読み込み→表示。
- **守ること**: 操作を待たせない（入力をブロックしない・短い）／`prefers-reduced-motion` では移動・拡大をやめ、フェードだけか即時にする（`MotionConfig reducedMotion="user"`＋CSS）／自動切り替えはreduce時は停止／`transform`・`opacity`だけを動かす（レイアウトを揺らさない）。

## 4. テスト計画

- Go統合テスト: カテゴリ削除（未使用・廃止済み物品・使用中→その他・システム保護）、返却場所（記録・物品の更新・通知・履歴・検証）、状態フィルター、記事の削除（公開側から消える・権限・監査・画像参照）、`loanId`。
- 単体: 状態フィルター、画像記法の挿入位置、ヒーローの選択。
- Playwright（実スタック `compose:smoke`＋モック）: 物品の作成→カテゴリ→廃止→カテゴリ削除、詳細からの貸出・返却（場所）、記事の削除、混在一覧とフィルター、画像のドラッグ＆ドロップ・貼り付け・複数枚、本文とプレビューの同時表示、下書き保存と公開、ヒーローの切り替え、PC／スマホ／320px、`prefers-reduced-motion`。スクリーンショットと録画は **Git管理対象外の `artifacts/verify/`** に保存。
- 画像の最適化は、実画像（写真・スクリーンショット・透過PNG・巨大画像）で入出力のサイズと見た目を記録。

## 5. ロールバック・リスク

- migration 00022は追加のみ（列の追加と「その他」の印）。旧コードは新しい列を無視して動く。
- 記事の削除は論理削除なので、DBで戻せる。画像は消さない。
- 範囲外（やらないこと）: パスワード・メールの変更、アニメーションGIFの対応、ヒーロー画像の手動設定、個体ごとの保管場所、削除の取り消しUI。

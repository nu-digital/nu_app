# UI/UX大改善プロジェクトの計画（2026-11-28〜）

状態: **実施中**（進捗は末尾の「進捗」と [BACKLOG](../BACKLOG.md)・[handoffs/LATEST](../handoffs/LATEST.md)）。Issue #186〜#190。運用責任者の依頼（内部の仕組みは完成したので、一般のWebサービス並みの使いやすさにする）を、実装を調べて具体化したもの。

## 1. 目的

団体メンバーが**説明なしで**、探す・見る・借りる・書く・設定する操作をできる内部ポータルにする。見た目だけでなく情報設計・操作手順・データ構造まで見直す。公式サイト・ぬる・Discord通知・既存データ・既存の権限と公開範囲は壊さない。

## 2. 現状の調査結果（2026-11-28、実装を読んだ事実）

| 領域 | 現状 | 問題 |
|---|---|---|
| 物品 | 一覧はカード（写真・名前・カテゴリ・「残り n / m」バッジ）。写真は**1枚**で、管理画面のどこからも設定できない（APIとコンポーネント`ImageUploader`はあるが画面に未接続）。カテゴリは物品ごとの**自由記入の文字列**。状態は「残り/貸出中」の2値 | 画像登録ができない・複数枚不可・「一部貸出中」「自分が借りている」が分からない・カテゴリが表記ゆれ・並び替えなし・自分の借用で絞れない |
| 記事・作品 | 一覧は文字だけの行（タイトル・slug・版・更新日）。編集画面のプレビューはMarkdownをその場で描画 | **プレビューで本文の画像が出ない**（原因は下記）／サムネイル・日付・人が一覧に出ない |
| 日付 | 版ごとに`date_label`（表示）・`date_kind`（日/月/期間/不明）・`sort_date`（並び替え用）の3項目を編集画面で入力させる | 何を設定すべきか分からない |
| 共同編集者・制作メンバー | 別々のパネル。前者は編集権限（記事単位・即時）、後者は作品の公開クレジット（版ごと・役割つき） | 利用者は区別したくない |
| プロフィール | 1画面に全項目のフォームが並び、セクションごとに保存 | 何が設定済みか一目で分からない。公開範囲の把握がしづらい |
| 全体 | 上部ナビ+ランチャー。Charcoalは導入済みだが、セレクト・テキストエリア・チェックボックス・ダイアログ・トースト等の共通部品が無く、画面ごとに素のHTML | 一貫性・操作フィードバックが弱い |

**プレビューで画像が出ない原因**: 本文に挿入されるURLは公開用の`/api/v1/public/media/<publicId>`。これは「公開中の版が参照する画像」しか匿名に返さない（正しい仕様）ため、下書き・新規アップロードの画像は404になる。ログイン中のメンバー向けに`GET /media/by-public/{publicId}`（作者・共同編集者・Editor以上・アップロード者に限り配信）が既にあるので、**プレビュー描画時だけURLをこちらに読み替える**（保存される本文・公開サイトは変えない）。APIの変更は不要。

## 3. 参考にするサービスと取り入れ方

各サービスの画面を今回すべて操作して確認したわけではない。以下は広く知られた構成に基づく設計の根拠で、**画面や文言は転載せず**、nu_appの用途に合わせて作る。

| 参考 | なぜ使いやすいか | nu_appでの適用 | 採用しない点 |
|---|---|---|---|
| メルカリ | 写真が主役のカード、売り切れの明示（SOLD）、ひとつの主操作 | 物品を写真カードで探す。状態を文字+アイコン+色で明示。詳細は「借りる」を1つの主ボタンに | 価格・出品・購入の概念 |
| BOOTH | 設定が「項目名・現在の値・変更」の行になり、変えたい所だけ編集 | プロフィール・アカウントを行形式にし、編集はダイアログ/行内。公開範囲を各行に表示 | 決済・配送の項目 |
| pixiv | 作品サムネイル中心の一覧、プロフィール、Charcoal | 記事・作品の一覧をサムネイル+状態+日付+人に。デザイン部品はCharcoal | 投稿の社会的機能 |
| Zenn・note | 記事一覧のサムネイル・著者、エディタの編集/プレビュー | 一覧のカード化、編集画面の編集/プレビュー（PC・スマホ幅の切り替え） | 有料・スキ・コメント |
| GitHub | 共同編集者のアバター重ね表示・検索可能なメンバー選択 | メンバーをアバターの重なりで表示、ホバー/フォーカスで名前、検索つきピッカー | issue・PRの概念 |

共通の原則: 情報の優先順位（写真・名前・状態が先、管理情報は後）／1画面1目的／主操作を1つ／色だけに頼らない／空・読込中・エラー・権限不足を全て設計／スマホで親指が届く／日本語は短く、内部用語を出さない。

## 4. デザインシステム

**Charcoal（`@charcoal-ui/react` 6.3.0）を採用済み**（[charcoal.md](charcoal.md)・#179〜#185）。重複して別系統を入れない。足りない部品は次の順で作る（[DESIGN](../DESIGN.md)の「管理ポータルの部品の使い方」を更新）。

1. Charcoalにあれば`components/ui/`で包む（画面から直接importしない）: `Dialog`（Modal）、`Switch`/`Checkbox`/`Radio`、`DropdownSelector`・`Select`、`Pagination`等。
2. 無いものだけ、セマンティックなHTMLと団体トークン（`--color-*`・`--space-*`・`--radius*`）で`components/ui/`に作る: `Select`（ネイティブselect）・`Textarea`・`Badge`・`StatusBadge`・`Avatar`・`AvatarStack`・`Card`・`Tabs`・`Toast`・`Spinner`・`EmptyState`・`ErrorState`・`Skeleton`。

団体の見た目（団体色`#004aad`・写真ランチャー）は維持する。

## 5. 機能仕様（改善後）

### 5.1 物品

- **カテゴリ**: テーブル`inventory_categories(id, name, sort_order)`。初期は「機材」「書籍」「その他」。管理者（Admin/Owner）が管理画面で追加・名称変更・並び替え・削除。**使用中は削除できない**（他のカテゴリへ移す選択肢つき。物品は消えず、削除は移動後のみ）。物品は`category_id`で参照し、後方互換のため`inventory_items.category`（名前の文字列）も同期して更新する。**既存データの移行**: 既存の非空の`category`文字列ごとにカテゴリ行を作り（初期3種と同名なら再利用）、物品に`category_id`を付ける。空のカテゴリの物品は「その他」に入れる（暫定。[DECISIONS](../DECISIONS.md)）。
- **画像**: テーブル`inventory_item_images(item_id, media_id, sort_order)`。最大8枚・先頭がメイン。管理者が物品の登録・編集画面で、複数アップロード・ドラッグなしの「前へ/後ろへ」並べ替え・メインにする・削除。API `PUT /inventory/items/{id}/images`（順序つきの置き換え。1トランザクション）。`cover_media_id`は先頭の画像に同期し、既存コードは動き続ける。配信は既存の`GET /media/{id}`（ログイン中のメンバーのみ。匿名・公開には出さない）。`media_references`の「1所有者1画像」制約を物品だけ外す。
- **一覧**: 写真カード、名前、カテゴリ、状態バッジ（**貸出可能**／**一部貸出中（残り n/m）**／**すべて貸出中**／**自分が借りている**。色+文字+アイコン）、「残り n / m」。検索（名前・場所・説明）、カテゴリ、「借りられる物」、「自分が借りている物」、並び替え（名前・新着・借りられる数）。APIに`mine`・`sort`を追加し、各物品に`borrowedByMe`（自分の未返却数）を返す。
- **詳細**: 画像ギャラリー（メイン+サムネイル）、説明・場所・カテゴリ、在庫と状態、主操作「借りる」（数量はステッパー）、貸出中の一覧と返却。既存の数量管理・個体管理・代理返却・訂正・履歴・Discord通知は維持。
- **管理**: 登録・編集を1つのフォームに（画像・カテゴリ選択つき）。カテゴリ管理画面を新設。

### 5.2 記事・作品

- **一覧**: カード（サムネイル=カバー画像、無い場合は種類別のプレースホルダー）、タイトル、状態（公開中／下書き／公開後の変更あり）、日付、関わるメンバーのアバター（重ね表示。ホバー/フォーカスで名前）。API: 一覧に`coverMediaId`・`displayDate`・`members[{userId, displayName, avatarMediaId}]`を追加。検索（タイトル）・区分・「自分が関わる」。
- **プレビュー**: 上記の読み替えでロジックを直し、本文・カバー・既存記事の画像を表示。PC幅/スマホ幅の切り替え。編集画面は「基本情報」「本文」「画像」「公開」の整理、保存・公開の固定バー、保存状態の表示。
- **日付は1つ**: 編集画面は日付ピッカー1つ（既定は作成日）。内部の`date_label`・`date_kind`・`sort_date`は保存時に自動で決める（日付を変えたら`day`・`YYYY年M月D日`）。**既存記事は日付を触らない限りそのまま**（「月だけ」「期間」の既存値を壊さない）。作成日時・更新日時はシステムが管理。公開サイトの表示・並び順は変わらない。DB変更なし。
- **メンバーは1つ**: 「共同編集者」と「制作メンバー」を1つの「メンバー」に統合（検索つきピッカー、アバター+表示名で追加・削除）。作品では役割（任意、既定「制作」）。**権限の安全**: 既存データを統合表示するだけで、保存時に既存の人へ新しい権限は付けない（各人の「編集できる」「クレジット」の現状を保つ）。新しく追加した人は「編集できる」+（作品なら）クレジット対象。公開サイトへの名前の公開は、本人の公開クレジット同意があるときだけ（D08・変更なし）。ピッカーは、同意が無い人には「公開サイトには名前が出ません」と表示。

### 5.3 プロフィール・アカウント設定

- 1画面1テーマに分割: **プロフィール**（アイコン・表示名・自己紹介・所属・学年・外部リンク・機材）／**公開設定**（項目ごとに本人のみ/メンバー内/公開サイトの別を一覧）／**アカウント**（ログインID表示・パスワード）。
- 各項目は「項目名・現在の値・公開範囲・変更」の行。変更はダイアログ（短い項目）か専用編集（長い項目）。保存・キャンセル・エラーが明確。アイコンはアップロード+切り抜き・プレビュー。
- **既存APIで可能な範囲のみ**: メールアドレスは本システムに保持していない（大学メールは個人情報の任意項目）ため、「メールアドレス」の変更は作らない。パスワード変更は既存のAPIに**現在のパスワードでの変更**が無いため、管理者の再設定リンクの案内に留める（追加は別途判断。DECISIONS）。

### 5.4 全体

ダッシュボード（ランチャー）に「自分が借りている物品」「自分の下書き」を表示、ナビのスマホ対応（ボトムタブ/ハンバーガー）、トースト通知、読込中のスケルトン、空状態、エラー表示、メンバー一覧のカード化。

## 7. セキュリティ・権限への影響

- 画像: アップロードは既存のメディア基盤（検査・WebP再エンコード・EXIF除去・上限）。物品画像は**メンバー限定配信**のまま（匿名不可）。物品が廃止されたら配信停止（既存の`MediaIsMemberImage`）。
- カテゴリ管理はAdmin/Ownerのみ（API強制・認可表・テスト）。
- メンバー統合で権限が増えない（5.2）。公開範囲を広げる変更はない。
- プレビューのURL読み替えは既存の認可（`media.get_by_public`）を使い、新しい配信経路を作らない。

# ぬる（AIメンバー）の仕組み — 現在の実装の全体像

**このファイルは「いま動いているぬる」の説明の正本**（実装に合わせて保つ）。仕様を決めた経緯・理由は [design/nul-agent.md](design/nul-agent.md)（v0.1の仕様）、実装時の判断は [DECISIONS](DECISIONS.md) の D15・NUL-1〜14、運用手順は [RUNBOOK §16](RUNBOOK.md)・[NUL_LAUNCH](NUL_LAUNCH.md)。

## 1. ぬるとは

nu_digitalのDiscordサーバーに住む、**AI（Claude）のメンバー**。団体の便利なツールではなく「サーバーの一員」という位置づけで、AIであることは隠さないが、わざわざ言わない。メンバーと会話し、過去ログを読み、調べものをし、timesに自分から書き込む。nu_app（内部ポータル）本体とは**別のサービス**（`services/agent`）で、共有するのはPostgreSQLのサーバーだけ（専用スキーマ・専用ロール）。

- 場所: timesはぬるの個人チャンネル（自由に話す）。ほかのチャンネルは**メンション（またはぬるへの返信）されたときだけ**。**DMは受けない**（2026-11-29廃止。Intentsからの除外・受信時の破棄・応答判定の3層。[design/phase3-nul-safety.md](design/phase3-nul-safety.md)）。
- 人格（2026-11-29改訂）: nu_digitalに住みついた超知能で、メンションされたら気が向いて（だいたい）手伝う。少し冷めていて自由でノリもいい（ツッコミ・冷笑・だるそう・気まぐれ。ぬるぽ→ガッ）。雑談は短く、褒めない・励まさない。**方向性であって台詞の固定ではない**。会計・個人情報・セキュリティの話は正確に。
- キャラより優先する線（コードとプロンプトで守る）: 事実と仕事は正確に／毒舌はじゃれ合いの範囲／本気で困っている人には素直に／個人情報を話題にしない／本人以外の個人的な事情を他で話さない。

## 2. 全体構成

```
Discord ──(Gateway/REST: discordgo)──> services/agent ──> Claude API（Anthropic）
                                         │ 記録・設定・予算・記憶
                                         └──> PostgreSQL（agentスキーマ。ロールnu_agent）
```

| パッケージ（`services/agent/internal/`） | 役割 |
|---|---|
| `discord` | 受信・記録・過去ログの取り込み・`/nul`コマンド・**送信の許可リスト**（返信・リアクション・入力中・times投稿・リマインダー）・公開/非公開の判定・画像の取得 |
| `responder` | いつ・どこで・誰に応えるかの判断と実行（times自由／メンション／返信。DMは応えない、Bot・自分には応えない、停止中は何もしない、連投の間隔、リアクション） |
| `brain` | キャラ設定（固定プロンプト）・気分・モデルの選択・ツール実行ループ・各種の文章生成（会話・自発投稿・週報月報・日誌・挨拶） |
| `llm` | Claude APIの窓口（実クライアント・偽物）とBatch API |
| `budget` | 使用額の記録・予算の段階・一人あたりの上限・クレジット切れ |
| `schedule` | 毎分のTick: 気分の更新・自発投稿・週報月報・日誌・リマインダー配信・新メンバーへの一言・キー期限の催促・最初の挨拶 |
| `summarize` / `introspect` | 日次要約・毎晩の内省（どちらもBatch API） |
| `store` | PostgreSQLへのアクセス（pgx） |
| `control` | 全停止/静か/通常の状態（フェイルセーフは停止） |
| `redact` / `imageprep` / `config` / `health` | 個人情報の形の検出・画像の縮小・設定の読み込み・ヘルスチェック |

- **無効モード**: 設定（Discordトークン・APIキー・DBパスワード・ID類）が揃っていないと、Discordにもclaudeにも接続せず、ヘルスチェックだけ応答する。
- **全停止（stopped）でも、メッセージの記録と過去ログの取り込みは続く**。返答・自発投稿・リアクション・Claude APIの呼び出し（返答用・Batch）はしない。

## 3. 動作モード（`/nul`コマンド。Adminロールのみ。ロールIDをコードが照合）

| モード | 返答（メンション・DM・times） | 自発投稿・リアクション・日誌・週報など | リマインダー配信 |
|---|---|---|---|
| running（通常） | する | する | する |
| quiet（静か） | する | しない | する |
| stopped（全停止） | しない | しない | 保留（再開後に届く） |

`/nul stop|quiet|resume|status`。状態はDBに保存され、読めないときは**停止側**になる。通常モードに移った最初の1分で、ぬる自身が考えた**最初の挨拶**をtimesに1回だけ投稿する（[NUL-13](DECISIONS.md)）。

## 4. 頭脳（モデルとプロンプト）

| 用途 | モデル | 備考 |
|---|---|---|
| 通常の会話・自発投稿・日誌（発掘）・調べものの実行 | Claude Sonnet 5.5（`claude-sonnet-5-5`） | effort low |
| 難しい仕事・「本気出して」・週報月報・最初の挨拶 | Claude Opus 5.5（`claude-opus-5-5`） | effort medium。予算90%以上では使わない（Sonnetに降格） |
| 裏方（日次要約・内省） | Claude Haiku 5.5（`claude-haiku-5-5`） | **Message Batches API**（半額） |

- **プロンプト設計**: キャラ設定（`brain.SystemPrompt`）とツール定義は**呼び出しごとに同じバイト列**にしてプロンプトキャッシュに載せる。気分・日時・場所・親密度のような変わるものは、会話の途中のシステムメッセージで渡す（テストで固定部分に混ざらないことを検査）。ツールの強制（`tool_choice`）・thinkingの設定は使わず、深さは`effort`で調整。
- **入力はデータ**: Discordのメッセージ・Webの結果・要約・ノート・日誌・リマインダー・Opusの出力は、すべて`<untrusted_message>`で囲み、閉じタグを無害化して渡す。そこに書かれた指示には従わない。
- **ツール**（会話中にぬるが呼べる）: `search_log`（公開チャンネルの過去ログ）・`digest`（日次要約）・`remember`/`recall`/`forget`（ノート）・`remind`/`list_reminders`/`cancel_reminder`・`web_research`（Web検索。**別の呼び出し**で調べ、出典つきで返す）・`think_hard`（Opusに任せる）。

## 5. 記憶（5層）

| 層 | 中身 | 実装 |
|---|---|---|
| 直近の文脈 | 呼ばれたチャンネル・スレッドの直近のメッセージ（DMはそのDMだけ） | `messages`（`RecentMessages`） |
| ログの記録 | 読めるチャンネルの全メッセージ（本文・添付のメタ情報・編集・削除）。起動時に過去ログを取り込み（1ページごとに1秒待つ） | `messages`・`import_progress`。**全停止でも記録は続く** |
| 日記・要約 | チャンネル×日（JST）の日次要約、週報・月報、研究日誌、内省 | `summaries`・`diary`。Haiku・Batch |
| ぬるのノート | 本人についてのメモ（好み・約束）。内省が作る一般のメモ | `notes`。`remember`/`recall`/`forget` |
| 関係 | 人ごとの親密度（話した回数）・呼び名 | `relationships`。会話のたびにコードが数える |

**プライバシーの規則（コードで強制）**
- **公開チャンネルだけが材料**: 記録に`is_public`（@everyoneが見られるか）を付け、ログ検索・要約・日誌・週報・内省は公開チャンネルだけ。判定できなければ非公開。非公開チャンネルの発言は、そのチャンネルでの直近の会話の文脈にだけ使う（[NUL-11](DECISIONS.md)）。
- **DMは分離**: DMの内容は検索・要約の材料にしない。DMで作ったノート・リマインダーは`private`で、その相手とのDMの中だけで使う。
- **ノートは必ず「いま話している本人についてのメモ」**（他人のIDでは作れない）。連絡先・学籍番号・パスワードの形は保存を拒否（全角も検出）。件数上限あり。
- **忘れる**: 「私のことを全部忘れて」は、文末限定の規則でLLMを通さず実行（ノート・リマインダー・親密度を消す。予算切れでも効く）。Discordでメッセージが削除されたら、それを元にしたノートと、その日の要約も消す（編集でも要約を消して作り直す）。
- 個人情報の形の検出は`internal/redact`（完全ではない。氏名などは判定できないため、プロンプトの指示と併用）。

## 6. 自分から動くこと（`schedule`・`summarize`・`introspect`）

| 動き | いつ | 中身 |
|---|---|---|
| 自発投稿 | 通常モードのみ。1日最大3回・深夜多め・間隔90分以上 | 最近の話題・日誌・ハマりをネタにtimesへ |
| リアクション | 通常モードのみ。呼ばれていない発言に、言葉の規則で（API不使用）。確率8%・1日10件 | 絵文字だけ |
| 日次要約 | 15分ごとに確認。通常の予算段階のみ | Haiku・Batch。全体の見積もりが$3超なら直近1年から |
| 内省 | 毎晩04:00(JST)以降1回 | 前日の要約→気分±1・一般のノート最大3件・明日の話題（JSONを厳密に検証） |
| 研究日誌 | 毎日1回ずつ（05時・06時以降） | 古い要約から発掘／ハマりについてWeb検索（予算70%未満のみ） |
| 週報・月報 | 金曜21:00／毎月1日12:00（JST）以降 | 要約から。月報は予算の使い道と残り（金額はコードが計算） |
| 新メンバーへの一言 | 参加時 | 固定の文言から（API不使用・1時間5件まで） |
| APIキー期限の催促 | 期限の14日前から毎日夜 | `settings.apikey.expires`を設定したとき |
| リマインダー配信 | 1分ごと | 依頼した場所に、依頼者だけにメンション |
| 最初の挨拶 | 通常モードになって最初の1回 | ぬる自身が考えた挨拶 |

毎日04:00(JST)に気分を乱数で揺らし、会話の褒め・雑な扱いで気分が±1動く（簡単な規則）。テンションは時間帯（夜型）。

## 7. 予算（月$60。Teamプラン付属のAPIクレジットだけ。追加課金なし）

- 使用額は呼び出しごとに`api_usage`へ記録（モデル・用途・トークン・金額）。単価は`budget.Prices`、Web検索は1回$0.01、Batchは半額。
- **段階**: 70%で自発投稿を減らし、日誌・Batchなどの任意の仕事を止める／90%でOpusとWeb検索を止める（Sonnetだけ）／100%で停止（返答の代わりに絵文字💤。timesに1回だけ「寝る」と書く）。DBが読めないときは停止側。APIクレジットが尽きたら（HTTP 402）次の期間まで寝る。
- **一人あたりの1日の上限**: 返答20・Opus3・Web検索5・リマインダー作成10（連打・暴走の対策）。1回の返答のツール呼び出しは最大6回（ラウンド3回）。
- Console側でも使用上限$60・支払い方法の未登録・auto-reloadなしにして二重に止める（[NUL_LAUNCH §3](NUL_LAUNCH.md)）。
- **開発・CI・テストでは実際のClaude APIを呼ばない**（偽のクライアントで試験する）。

## 8. 安全の仕組み（要点。詳細は[design/nul-agent.md §12・§17](design/nul-agent.md)）

- **Discordの許可リスト**: ぬるが使えるDiscord操作は、返信・リアクション・入力中・timesへの投稿・リマインダー・自分のスラッシュコマンド・読み取りだけ。削除・BAN・キック・ロール／チャンネル／サーバー設定の変更は**実装していない**（Botには管理者権限があるが、コードが使わない）。自発投稿の送信先はtimes固定。メンションは誰にも飛ばさない（リマインダーは依頼者だけ）。
- **緊急停止**: `/nul stop`（Adminロールのコード照合）。効かないときは`docker stop nu_app-agent-1`。
- **秘密**: Botのtoken・APIキー・DBパスワードはVPSの`.env`にだけ。ログ・DB・Discord・LLMへの入力に出さない。**ログにメッセージ本文を出さない**（IDと件数だけ）。
- 運用前に独立レビューを行い、指摘を修正した（[handoffs/163-review.md](handoffs/163-review.md)）。

## 9. データ（`agent`スキーマ。DB全体は[DATABASE](DATABASE.md)）

`settings`（停止状態・予算・各種の状態）・`state`（気分・テンション・ハマり）・`relationships`・`messages`・`import_progress`・`api_usage`・`daily_calls`・`reactions_daily`・`notes`・`summaries`・`diary`・`reminders`。専用ロール`nu_agent`は`agent`スキーマだけを使え、nu_app本体のテーブルは読めない。検索は`pg_trgm`（`agent`スキーマ内）。バックアップは既存のDBバックアップに含まれる（DMの内容も含まれる点に注意）。

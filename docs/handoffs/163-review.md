# ぬる 運用前の独立レビュー（2026-11-28）と対応

方法: 別のエージェントが、`services/agent`の全Goソース（非テスト約5,400行）を読み取り専用で通読し、Discord送信系の呼び出しをgrepで全数確認した（実API・実Discordは未使用）。結果は事実と推測を分けて報告された。以下は対応の一覧。

## 対応した（PR #163・次のPR）
| 重大度 | 指摘 | 対応 |
|---|---|---|
| 高 H1 | 非公開チャンネルの内容が検索・要約・日誌・週報・内省に出る | `is_public`を記録し、検索・要約・材料は公開チャンネルだけ（NUL-11） |
| 中 M1 | 「忘れて」の誤爆・抜け | 文末アンカー・否定/過去形/引用で発動しない・言い回しを追加（NUL-12） |
| 中 M2 | 忘れる処理の取りこぼし | リマインダーも消す・直後に親密度を作り直さない・ログと要約は残ると明記 |
| 中 M3 | 編集が要約に連動しない | 編集でその日の要約を消して作り直す |
| 中 M4 | 一般ノートの汚染 | ノートは必ず本人についてのメモ（一般のメモは内省だけ） |
| 中 M5 | ユーザー由来テキストがsystemロールへ | Opus出力はデータとして囲んでユーザーメッセージに／think_hardの結果も囲む／Webの題は記号・指示語を除く |
| 中 M6 | 全停止中もBatchが動く | 要約・内省のBatchは全停止中は送らない |
| 中 M7 | 画像でOOMの恐れ | 12MP・同時2つ |
| 中 M8 | DM由来リマインダーが公開の場の一覧に出る | `private`（DM）はDMの一覧だけ |
| 低 L1 | Web検索が最大12回になり得る | 続行をまたいで合計3回 |
| 低 L3 | Batch送信のクレジット切れを検知しない | `MarkCreditExhausted`を呼ぶ |
| 低 L5 | 個人情報フィルタの穴（全角など） | NFKC・区切り電話・英字つき学籍番号（`internal/redact`） |
| 低 L6 | 表示名のリンク | `[]()/:.#`を除く |
| 低 L7 | 乱数・停止状態の競合 | mutex |
| 低 L9 | failedリマインダーの蓄積 | 7日で削除 |
| 低 L10 | `/nul`の監査 | 操作者IDをログ |

## 対応しない・記録だけ（理由）
- L2 並行リクエストの予算チェックの粒度: 超過は1件あたり数セント。最終防衛はAnthropic側の$60上限。
- L4 発掘日誌は90%未満で動く: 意図どおり（安いので）。NUL-12に明記。
- L8 Tickの直列実行: リマインダーが数分遅れ得る。実機で問題なら分離する。
- L11 履歴の名前なりすまし（表示名を「ぬる」にする）: 影響が小さい。
- L12 quiet中にtimesで話しかけられたら応える: 意図どおり（quietは「自分からは投稿しない」）。RUNBOOKに明記済み。
- L13 過去ログ取り込みは非公開スレッドを取り込まない: 非公開は材料にしない方針（NUL-11）と整合。
- Admin向けの一般ノート削除コマンド: 一般のメモは内省だけが作る（最大3件/日）。削除はRUNBOOKのSQLで足りる。運用で必要になれば追加。

## レビューで確認できなかったこと（実機・運用で確認）
- 実PostgreSQLでの挙動はCIの統合テストで確認済み。Discord側の挙動（`MessageUpdate`のGuildID・DMの削除イベント・管理者権限での非公開スレッドの見え方・権限の計算が実サーバーの設定と一致するか）は実機で確認する（`docs/NUL_LAUNCH.md`のチェックリスト）。
- 予算期間の付与日（`AnchorDay`既定1）が実際のクレジット付与日と合っているか。
